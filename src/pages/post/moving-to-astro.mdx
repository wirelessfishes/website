Okay so some context, my site has used the [Eleventy](https://www.11ty.dev/) static
site generator ever since the commit
[141d103](https://github.com/wirelessfishes/website/commit/141d103337e7ba7e349cec8d05aa5660aa627680)
(2025/06/07 - wow that's 7 months ago). This was what I would call an "alright" decision,
since I only really needed to avoid copy-pasting my navbar on every page.

11ty rocks (so does their mascot)! It is perfect for inserting html snippets and creating
simple blogs. However the problem arises when you try to do anything more than that. When I
wanted to go from simple html snippets to full blown components, Eleventy just does not have a
simple way of doing that. And then you end up manually manipulating the DOM just do make
a guestbook. [Ask me how I know](https://github.com/wirelessfishes/website/blob/52f49ba1e4f89ac7559efc5e938e10c9957563e5/src/scripts/guestbook.ts).

Needless to say that combined with the lacking documentation (it's bearable only when you use an AI
chatbot to search for stuff) has made me want to move away more and more. So I've bitten the bullet
and ported the whole website to Astro+Svelte over the course of 5 days.

## The good

### Community

Documentation is now actually useful, yay! Both Astro and Svelte have good docs
and combined with their large communities make it way easier to troubleshoot things.

### Integration

Integrating Svelte into Astro is as easy as:

```bash
pnpm astro add svelte
```

So convenient!

### Components!!!! &lt;3

Now that I have the power of components on my side, I can do what Eleventy can only dream of:

```svelte
<AeroButton color={"#1e78ff"}>Button 1</AeroButton>
<AeroButton color={"#9d41da"}>Button 2</AeroButton>
<AeroButton color={"#ffb41f"}>Button 3</AeroButton>
<AeroButton color={"#ff1e1e"}>Button 4</AeroButton>
<AeroButton color={"#ec5757"}>Button 5</AeroButton>
```

The snipped above produces this:

<AeroButton color={"#1e78ff"}>Button 1</AeroButton>
<AeroButton color={"#9d41da"}>Button 2</AeroButton>
<AeroButton color={"#ffb41f"}>Button 3</AeroButton>
<AeroButton color={"#ff1e1e"}>Button 4</AeroButton>
<AeroButton color={"#ec5757"}>Button 5</AeroButton>

See that? The button component automatically computes it's colors based on
one color you pass to it! So cool!

It uses the `color` npm package to work with colors and essentially does this:

```ts
let border = original_color.lighten(0.5).fade(0.5);

// Regular colors
let regular = {
  base: original_color,
  lighter: original_color.lighten(0.3),
};

// Colors for hovering over the button
let hover = {
  base: regular.base.darken(0.15),
  lighter: regular.lighter.darken(0.15),
};
```

Foolproof? No. Could it be done with less scripting and more css? Sure. But I like this
one, I've made it. This one is mine. And I am happy with it (for now lol).

### Interactivity / scripting

Another thing Astro+Svelte allows me to do is update the DOM (webpage content) very easily! I can
simply define a variable with `$state()` (in Svelte components), use it in a page
and whenever the variable changes, so does the webpage content!

<ChangingShowcase client:only />

The above example _roughly_ requires me to do this (not valid code):

```svelte
<script>
// import {sleep} from ...
let words = ["I can", "make these", "words change", "very easily", "with svelte!"];
let current_word: number = $state(0);

while (true) {
  current_word += 1;

  if (current_word >= words.length) {
    current_word = 0;
  }

  await sleep(1500);
}
</script>

<div>
  {words[current_word]}
</div>
```

This doesn't look that different compared to just updating the element's content directly with
`document.getElementById()` and changing it's `innerHtml`. But that gets messy fast
with every new element that need changing. Also the Eleventy approach would most
likely have you split HTML, CSS and Javascript into multiple files whereas Svelte
components contain everything in one, making it way easier to navigate the codebase.

This is extremely useful for things like... [my guestbook](/guestbook/)
(which you should definitely sign btw) or the status thingies on the
left sidebar! The files contain everything they need to function on their own and I can
just build site as if I was playing with LEGO. And if something needs changing,
everything related to one building block is contained within itself \:D

## The bad

So far I haven't had any issues with Astro. It has everything I need and the rest can
be added with additional npm packages. I'm looking forward to working with astro more.

## Would you recommend Eleventy/Astro?

Eleventy is honestly not the worst, but it has significantly more friction when configuring
compared to astro. If all you need is simple layouts and html snippets and don't mind the
config, it's probably right for you. Though if you need anything more (you probably do,
svelte components are awesome if not only for the scoped styles) you'll want to run Astro
together with another framework like Svelte.

Astro's nice, it compiles to a static pages just like Eleventy (perfect for nekoweb/neocities)
and stays fast thanks to javascript islands (honestly I still don't really understand
it fully, so [here's](https://docs.astro.build/en/concepts/islands/) a link).
